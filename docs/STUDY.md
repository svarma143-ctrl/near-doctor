# Study: near-doctor's static rules on public hackathon repositories

Generated by `scripts/study-report.mjs` from a `scripts/study.mjs` run. Counts only; no repository is named.

## Method

- 150 public GitHub repositories whose README mentions "NEAR HACKATHON", created after 19 Oct 2026, found with the unauthenticated GitHub search API, 50 JavaScript, 50 Rust, 50 TypeScript. Forks, archived repos and repos over 30 MB were skipped. 0 repositories failed to download.
- Each repository was downloaded as a source tarball and scanned **statically** by near-doctor (no project code was executed or compiled). Historical rules were included so they could be counted separately.
- The rules were audited by reading the flagged source in a random sample of hits, and **corrected four times** (one rule each) during this study (see "What the study changed"). The numbers below are from the corrected rules.

## What the study does and does not show

- It is a convenience sample of hackathon repos, not a random sample of NEAR code. It shows that these patterns occur in real code; it does not estimate how common they are in general.
- A finding is a source-level match. Flagged repos were not compiled, because building a stranger's repository runs its build scripts. The underlying behavior of F-004 was reproduced on a fixture with `cargo near check --clippy`.
- Build-breaking problems (F-001, F-008) have no hits because published code has already been fixed. Those rules help while writing code, not when auditing finished repos.
- Precision was checked by hand on a sample of hits (reading the raw source), not measured on the full set.

## What the study changed

The first version of the rules had false positives that unit tests and fixtures did not catch:

1. F-004 flagged methods that already carry `#[allow(clippy::too_many_arguments)]`. Testing showed a method-level allow silences the wrapper, an impl-level allow does not. (79 findings in 41 repos dropped to 28 in 21.)
2. F-012 checked a nested crate's test files against the root `Cargo.toml`, treated virtual workspace roots as crates, and flagged files Cargo never compiles. (8 findings dropped to 0.)
3. F-005 fired on any file that mentioned `balance`; it now needs a balance read and an assert, ignores the `.balance(..)` builder, and is `info`.
4. F-006 fired on read-only `provider.callFunction[Raw]` calls and on identifiers that contain the word `Failure`; it now needs near-api-js, an Account receiver and the whole word.
